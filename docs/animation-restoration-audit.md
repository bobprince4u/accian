UX rationale: the UX report and diff prioritize readable server output, keyboard/native controls, responsive progress, real destinations and reduced motion. The old hidden-before-observer implementation was unsafe without JavaScript. Restore visual language rather than that visibility dependency. No evidence supports Framer Motion, page route transitions, footer scroll reveal, nav entrance/scroll header effects, rating stagger or upload success effects; these are not fabricated.

## Browser finding during restoration

Production browser checks revealed that the existing footer staff link was automatically prefetched on public pages. The unconfigured local staff gate correctly returns 503; those speculative requests produced console errors on every route. Set `prefetch={false}` on that single protected link. Its destination and server authentication behavior are unchanged. This also avoids an unnecessary request during public browsing.

Services and Research Support heroes were historically static. Their brief requested entrances are explicitly small enhancements using the established fade-up language; they are not claimed as recovered historical animations. Pre-consultation step/review fades and progress scaling, native FAQ answer fade, and project reveals are likewise small enhancements. Footer scroll reveal, navigation item stagger/header scroll effects, continuous marquee motion, rating animation, route transitions and unverified visual effects are deliberately not invented.
